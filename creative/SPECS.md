# Countdown Timer — Creative Specs

Hand this document to the design team as-is. It defines exactly what to
deliver so a background creative drops straight into the countdown timer
with no engineering back-and-forth.

The bundled `goodgood-bg.png` is **placeholder art** generated by
engineering — replace it with real creative built to this spec.

## The deliverable

One flat PNG per themed timer.

| Spec | Value |
| --- | --- |
| Format | PNG (opaque — no alpha needed; anything transparent renders over the theme's fallback color unpredictably, so just fill the full canvas) |
| Dimensions | **exactly 640 × 180 px** (the timer renders at 2× density; the email displays it at 320 × 90 CSS px) |
| Color space | sRGB |
| File size | keep the source PNG under ~200 KB (see "GIF color budget" below — simpler art also means a smaller animated GIF) |

If a campaign needs a different display size, engineering changes
`layout.width`/`layout.height` in `brand.config.ts` and tells you the new
canvas: it is always **2× the logical size** in each dimension.

## The timer zone (most important part)

The live countdown digits (`DD : HH : MM : SS` with small labels) are
drawn **on top of** your PNG, inside a reserved rectangle called the
timer zone. Everything else on the canvas is yours.

For the current `goodgood` theme the zone is:

```
Timer zone (in the 640×180 deliverable):  x 210 → 640, y 0 → 180
Your creative area:                       x 0 → 210 (full height)
```

┌──────────────┬──────────────────────────────────────┐
│              │                                      │
│  your art    │   TIMER ZONE — keep visually quiet   │
│  (lockup,    │   digits drawn here at runtime       │
│  logo, etc.) │                                      │
│              │                                      │
└──────────────┴──────────────────────────────────────┘
      210px                    430px

Rules for the timer zone:

- **No text, logos, or critical detail** — the digits cover it.
- **Keep it low-contrast and even.** A flat color or a very gentle
  gradient reads best behind ticking digits.
- **Contrast:** digits render in the theme's digit color (currently
  white `#FFFFFF`, labels `#CBB980`). The zone must give white text at
  least **4.5:1** contrast everywhere — in practice, keep the zone dark.
- The zone also hosts the expired-state message (e.g. "IT'S TEE TIME")
  centered in the same rectangle, so it must work with a single line of
  text as well as four digit groups.

The zone is configurable per theme (`layout.timerBox` in
`brand.config.ts`, in logical px — half the deliverable px). If a layout
calls for the timer somewhere else (bottom strip, right-aligned, full
bleed), agree the rectangle with engineering first and design around it.

## GIF color budget (why flat art wins)

Email countdown timers ship as animated GIFs, which are limited to
**256 colors per frame**. Consequences for creative:

- Flat colors, simple two-stop gradients, and crisp vector shapes
  reproduce essentially perfectly.
- Photography, noise/grain textures, and long multi-hue gradients get
  quantized — expect visible banding — and inflate the animated GIF's
  file size (60 frames ship per image).
- Avoid fine text or hairline detail smaller than ~10 px in the
  deliverable; GIF quantization softens it.

If the campaign concept really wants photography, the recommended
pattern is: photographic hero as a **separate static image slice in the
email HTML** above/below the timer, and a flat graphic treatment for the
timer strip itself. Best of both — the photo stays full-fidelity JPEG.

## Optional: opening animation (intro header)

A theme can open with a short animation: the GIF holds on a "from"
header image, crossfades into the countdown creative, then ticks down.
The bundled `golfgalaxy-header.png` is placeholder art for the Golf
Galaxy → Good Good Open transition.

If a campaign wants an intro, deliver a **second** PNG for the opening
header to the **exact same spec as the background** above (640 × 180 px,
opaque, sRGB). Design it as a standalone title card — it fills the whole
canvas and has no timer zone, since the countdown hasn't appeared yet.
The crossfade into the main creative is generated automatically; you
only supply the two end-state PNGs. Timing (hold + fade duration) is set
per theme in `brand.config.ts` (`intro.holdMs`, `intro.transitionMs`).

Keep intro art flat/graphic for the same GIF-color-budget reasons — and
note the intro adds frames, so it increases the animated GIF's file size
(the Good Good demo runs ~670 KB with the intro vs ~550 KB without).

## Handoff

1. Name the file after the theme: `<theme>-bg.png` (e.g.
   `goodgood-bg.png`), plus `<brand>-header.png` for an optional intro,
   and drop them in this `creative/` folder.
2. Engineering points the theme's `background.imagePath` at it (or just
   overwrites the existing file for an existing theme — no code change).
3. Verify on the preview page (`/`): the themed example renders live,
   including the expired state.

Also supply, per campaign: the deadline (with timezone), the expired
message copy, and the live-text fallback line for the email ("Ends
Friday at midnight ET") — that line ships as real HTML text next to the
timer for recipients with images off.
